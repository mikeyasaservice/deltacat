# Metadata Caching

DeltaCAT's metadata caching system reduces catalog API calls and improves query performance by caching frequently accessed metadata with configurable TTL (Time-To-Live) support.

## Cache Architecture

The caching system supports three backend options with automatic failover:

<CardGroup cols={3}>
  <Card title="Memory (LRU)" icon="microchip">
    In-process caching with LRU eviction for single-node deployments
  </Card>
  <Card title="Redis" icon="database">
    Distributed caching for multi-node deployments with persistence
  </Card>
  <Card title="Memcache" icon="server">
    High-performance distributed caching for ephemeral data
  </Card>
</CardGroup>

## Configuration

### Basic Setup

```python
from deltacat.config.performance import MetadataCacheConfig, CacheBackend

config = MetadataCacheConfig(
    enabled=True,
    backend=CacheBackend.MEMORY,  # or REDIS, MEMCACHE
    default_ttl=300,              # 5 minutes default TTL
    max_memory_items=1000,        # Max items in memory cache
    max_memory_size_mb=100        # Max memory usage in MB
)
```

### TTL Configuration

Different types of metadata can have different TTL values:

```python
config = MetadataCacheConfig(
    schema_ttl=600,       # 10 minutes for schemas
    manifest_ttl=300,     # 5 minutes for manifests
    table_list_ttl=60,    # 1 minute for table lists
    namespace_ttl=600,    # 10 minutes for namespaces
    default_ttl=120       # 2 minutes for everything else
)
```

### Redis Backend

```python
config = MetadataCacheConfig(
    backend=CacheBackend.REDIS,
    redis_host="localhost",
    redis_port=6379,
    redis_db=0,
    redis_password="secret",
    redis_ssl=True,
    key_prefix="deltacat:"  # Prefix for all cache keys
)
```

### Memcache Backend

```python
config = MetadataCacheConfig(
    backend=CacheBackend.MEMCACHE,
    memcache_servers=[
        "cache1.example.com:11211",
        "cache2.example.com:11211"
    ],
    memcache_timeout=1,
    memcache_connect_timeout=1
)
```

### Environment Variables

```bash
# Cache backend selection
export DELTACAT_CACHE_ENABLED=true
export DELTACAT_CACHE_BACKEND=redis  # memory, redis, or memcache

# TTL settings (seconds)
export DELTACAT_CACHE_TTL=300
export DELTACAT_CACHE_SCHEMA_TTL=600
export DELTACAT_CACHE_MANIFEST_TTL=300

# Redis configuration
export DELTACAT_REDIS_HOST=localhost
export DELTACAT_REDIS_PORT=6379
export DELTACAT_REDIS_PASSWORD=secret
```

## Usage Examples

### Automatic Caching

The cache is automatically used by catalog operations:

```python
from deltacat.sql.catalog_adapter import CatalogAdapter

# Caching is enabled by default
adapter = CatalogAdapter(catalog_name="my_catalog")

# First call - fetches from catalog and caches
tables1 = adapter.list_all_tables()  

# Second call - returns from cache (60-80% faster)
tables2 = adapter.list_all_tables()
```

### Manual Cache Management

```python
from deltacat.catalog.cache.metadata_cache import get_metadata_cache

cache = get_metadata_cache()

# Set a value with specific TTL
cache.set(
    key="my_table_schema",
    value=schema_object,
    cache_type="schema",  # Uses schema_ttl
    ttl=3600  # Override TTL to 1 hour
)

# Get a cached value
schema = cache.get("my_table_schema", cache_type="schema")

# Check if key exists
if cache.exists("my_table_schema"):
    print("Schema is cached")

# Delete specific key
cache.delete("my_table_schema")

# Clear entire cache
cache.clear()
```

### Cache Key Management

```python
cache = get_metadata_cache()

# Create structured cache keys
key = cache.make_cache_key("catalog", "namespace", "table", "v1")
# Returns: "catalog:namespace:table:v1"

# Cache with structured keys
cache.set(key, table_data, cache_type="table")
```

## Cache Strategies

### Memory Cache (LRU)

Best for single-node deployments:

```python
config = MetadataCacheConfig(
    backend=CacheBackend.MEMORY,
    max_memory_items=1000,    # Limit number of cached items
    max_memory_size_mb=100    # Limit total memory usage
)
```

Features:
- Least Recently Used (LRU) eviction
- Automatic memory management
- No external dependencies
- Thread-safe operations

### Redis Cache

Best for distributed deployments:

```python
config = MetadataCacheConfig(
    backend=CacheBackend.REDIS,
    redis_connection_pool_kwargs={
        "max_connections": 50,
        "socket_keepalive": True,
        "socket_keepalive_options": {
            1: 1,  # TCP_KEEPIDLE
            2: 1,  # TCP_KEEPINTVL
            3: 3,  # TCP_KEEPCNT
        }
    }
)
```

Features:
- Shared cache across nodes
- Persistence options
- Pub/sub for cache invalidation
- Cluster support

### Memcache

Best for high-performance caching:

```python
config = MetadataCacheConfig(
    backend=CacheBackend.MEMCACHE,
    memcache_servers=["server1:11211", "server2:11211"],
    # Automatic consistent hashing across servers
)
```

Features:
- Fastest cache backend
- Automatic sharding
- Simple protocol
- No persistence

## Cache Invalidation

### Manual Invalidation

```python
cache = get_metadata_cache()

# Invalidate specific table
cache.delete("catalog:namespace:table_name")

# Invalidate all tables in namespace
cache.delete("catalog:namespace:*")  # Pattern-based deletion

# Clear entire cache
cache.clear()
```

### Automatic Invalidation

Cache entries automatically expire based on TTL:

```python
# Short TTL for frequently changing data
config.table_list_ttl = 60  # 1 minute

# Longer TTL for stable data
config.schema_ttl = 3600  # 1 hour
```

## Best Practices

### TTL Tuning

Set TTL based on data volatility:

- **Table lists**: 30-60 seconds (frequently updated)
- **Schemas**: 5-10 minutes (occasionally updated)
- **Manifests**: 2-5 minutes (moderate updates)
- **Namespaces**: 10-30 minutes (rarely updated)

### Cache Sizing

```python
# For development
config = MetadataCacheConfig(
    max_memory_items=100,
    max_memory_size_mb=10
)

# For production
config = MetadataCacheConfig(
    max_memory_items=10000,
    max_memory_size_mb=1000
)
```

### Cache Warmup

Pre-populate cache for better initial performance:

```python
def warmup_cache():
    adapter = CatalogAdapter("my_catalog")
    
    # Pre-cache all tables
    tables = adapter.list_all_tables()
    
    # Pre-cache frequently used schemas
    for namespace, table in tables[:10]:
        adapter.get_table_schema(table, namespace)
```

## Troubleshooting

### Cache Misses

High cache miss rate indicates:
- TTL too short
- Cache size too small
- Ineffective cache keys

```python
# Increase TTL
config.default_ttl = 600  # 10 minutes

# Increase cache size
config.max_memory_items = 5000
```

### Memory Issues

If memory usage is too high:

```python
# Reduce cache size
config.max_memory_size_mb = 50

# Use Redis or Memcache instead
config.backend = CacheBackend.REDIS
```

### Disable Caching

If you encounter issues:

```bash
# Via environment variable
export DELTACAT_CACHE_ENABLED=false

# Or programmatically
config = MetadataCacheConfig(enabled=False)
```

## Performance Impact

Metadata caching provides dramatic improvements:

- **API Calls**: 60-80% reduction in catalog API calls
- **Query Latency**: 50-70% reduction for metadata-heavy queries
- **Throughput**: 3-5x improvement for list operations
- **Network Traffic**: 70% reduction in catalog network traffic

The benefits are most significant for:
- Repeated queries to the same tables
- Table listing operations
- Schema introspection
- Multi-table joins
